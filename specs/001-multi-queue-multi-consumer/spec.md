
# 多队列多消费者架构

## 1. 功能概述

本功能实现**多队列多消费者**架构模式，每条队列只处理一种消息类型，支持同一队列多个消费者并行消费。

### 1.1 业务背景

当前系统使用单一任务队列存储所有类型消息，存在以下问题：
- 不同类型任务混合存储，难以独立扩展
- 同一类型任务只能串行处理，吞吐量受限
- 队列堵塞会影响所有类型任务

### 1.2 目标

实现消息类型级别的队列隔离，支持：
- 每种消息类型独立队列
- 同一队列多消费者并行处理
- 灵活的消费者数量配置

## 2. 用户场景

### 场景1：批量文件导入

**用户**：系统管理员  
**场景**：一次性向 `sources` 目录添加100张图片  
**期望**：系统能够并行处理这些文件，提高导入速度

### 场景2：混合任务处理

**用户**：系统用户  
**场景**：同时进行文件导入、导出和扫描操作  
**期望**：不同类型任务互不干扰，各自独立处理

### 场景3：动态扩展

**用户**：系统管理员  
**场景**：文件处理任务积压时  
**期望**：能够动态增加消费者数量加速处理

## 3. 功能需求

### 3.1 队列管理

| 需求编号 | 描述 | 验收标准 |
|---------|------|---------|
| FR001 | 支持按消息类型创建独立队列 | 每种消息类型有独立的队列存储 |
| FR002 | 支持动态创建新队列 | 新增消息类型时自动创建对应队列 |
| FR003 | 支持查询队列状态 | 可获取队列长度、待处理任务数等信息 |

### 3.2 消费者管理

| 需求编号 | 描述 | 验收标准 |
|---------|------|---------|
| FR004 | 支持同一队列多消费者并行消费 | 配置多个消费者后任务被均匀分配 |
| FR005 | 支持动态配置消费者数量 | 可在运行时调整消费者数量 |
| FR006 | 支持消费者负载均衡 | 任务在多个消费者间均匀分配 |

### 3.3 任务处理

| 需求编号 | 描述 | 验收标准 |
|---------|------|---------|
| FR007 | 任务按类型路由到对应队列 | 文件添加任务只进入 `source-file-add` 队列 |
| FR008 | 任务状态管理 | 支持 pending/running/done/failed 状态 |
| FR009 | 失败重试机制 | 任务失败后自动重试，达到最大重试次数标记为失败 |

## 4. 成功标准

### 4.1 性能指标

| 指标 | 目标值 | 说明 |
|------|-------|------|
| 单队列并行处理能力 | ≥3个消费者 | 同一队列可同时处理多个任务 |
| 任务分发延迟 | <100ms | 任务入队到被消费的时间 |
| 队列隔离性 | 100% | 不同队列任务互不影响 |

### 4.2 可用性指标

| 指标 | 目标值 | 说明 |
|------|-------|------|
| 任务丢失率 | 0% | 任务持久化存储，重启不丢失 |
| 失败重试成功率 | ≥95% | 可重试任务最终成功完成 |

## 5. 关键实体

### 5.1 队列（Queue）

| 字段 | 类型 | 说明 |
|------|------|------|
| name | string | 队列名称（消息类型） |
| consumerCount | number | 消费者数量 |
| pendingTasks | number | 待处理任务数 |
| status | string | 队列状态（active/inactive） |

### 5.2 任务（Task）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 任务唯一标识 |
| type | string | 消息类型（队列名称） |
| payload | object | 任务参数 |
| status | string | 状态（pending/running/done/failed） |
| retryCount | number | 已重试次数 |
| maxRetries | number | 最大重试次数 |
| createdAt | datetime | 创建时间 |
| updatedAt | datetime | 更新时间 |

---

## 6. 假设与约束

### 6.1 假设

- 系统运行在单进程环境下
- 使用 SQLite 数据库作为任务持久化存储
- 任务处理是幂等的（同一任务可重复执行）

### 6.2 约束

- 最大消费者数量不超过 CPU 核心数
- 任务重试次数不超过3次
- 任务处理超时时间为10分钟

---

## 7. 依赖关系

- **前置依赖**：现有的 SQLite 数据库和 Drizzle ORM
- **后置依赖**：队列消费者注册和任务处理器实现

## 8. 验收测试

### 8.1 队列隔离测试

**测试步骤**：
1. 向 `source-file-add` 队列添加5个任务
2. 向 `source-file-remove` 队列添加3个任务
3. 验证两个队列独立处理，互不干扰

**预期结果**：
- `source-file-add` 队列处理5个任务
- `source-file-remove` 队列处理3个任务
- 两个队列的任务不交叉处理

### 8.2 多消费者并行测试

**测试步骤**：
1. 配置 `source-file-add` 队列3个消费者
2. 添加6个任务
3. 验证任务被均匀分配到3个消费者

**预期结果**：
- 每个消费者处理2个任务
- 任务并行执行，总耗时约为单消费者的1/3

### 8.3 任务持久化测试

**测试步骤**：
1. 添加任务到队列
2. 停止服务
3. 重启服务
4. 验证任务恢复并继续处理

**预期结果**：
- 重启后任务状态保持不变
- 未完成的任务继续处理
