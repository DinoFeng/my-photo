## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添加并扫描照片源目录 (Priority: P1)

用户需要添加多个照片源目录到系统中，系统会扫描这些目录下的照片和视频文件并建立索引。系统不会移动或修改源目录中的文件，只读取元数据。

**Why this priority**: 这是核心功能，用户必须能让系统知道要管理哪些媒体文件才能继续使用其他功能。

**Independent Test**: 可以通过配置一个或多个照片源目录，验证系统是否能成功扫描并索引照片和视频，同时源目录中的文件保持不变。

**Acceptance Scenarios**:

1. **Given** 用户已启动应用，**When** 用户添加一个存在的照片源目录，**Then** 系统开始扫描该目录下的照片和视频文件并建立索引
2. **Given** 照片源目录已添加，**When** 系统扫描完成，**Then** 源目录中的照片和视频文件没有被移动、重命名或修改
3. **Given** 系统正在扫描，**When** 用户查看状态，**Then** 用户可以看到扫描进度

---

### User Story 2 - 从导入目录整理照片 (Priority: P1)

用户配置一个导入目录（如相机存储卡或下载目录），系统监控该目录，将新照片按照配置的组织规则（如按日期、相机型号等）复制或移动到照片源目录中。

**Why this priority**: 这是用户整理照片的主要方式，通过自动化导入减轻用户手动整理的负担。

**Independent Test**: 可以配置导入目录和组织规则，放入测试照片，验证系统是否能按规则整理照片到源目录。

**Acceptance Scenarios**:

1. **Given** 用户已配置导入目录和组织规则，**When** 导入目录中有新照片，**Then** 系统按规则整理这些照片到照片源目录
2. **Given** 照片已成功整理，**When** 检查源目录，**Then** 照片已按规则命名和组织
3. **Given** 整理过程中，**When** 出现重复照片，**Then** 系统按配置处理（跳过、重命名或覆盖）

---

### User Story 3 - 浏览和搜索照片 (Priority: P2)

用户可以通过 Web 界面浏览、筛选和搜索已索引的照片和视频。

**Why this priority**: 让用户能方便地找到和查看已管理的媒体，提供基础的查看功能。

**Independent Test**: 可以验证用户界面是否能显示照片/视频列表、支持按日期/类型筛选和按关键词搜索。

**Acceptance Scenarios**:

1. **Given** 用户访问应用界面，**When** 浏览照片，**Then** 系统显示已索引照片的缩略图和元数据
2. **Given** 照片已索引，**When** 用户按日期筛选，**Then** 系统显示该日期范围的媒体
3. **Given** 用户输入关键词，**When** 执行搜索，**Then** 系统返回匹配的照片和视频

---

### User Story 4 - 导出和整理照片 (Priority: P3)

用户可以将照片按照指定的组织方案批量导出到外部目录，便于备份或分享。

**Why this priority**: 提供额外的灵活性，让用户能按需要重新组织照片文件结构。

**Independent Test**: 可以选择一组照片和导出方案，验证系统是否按规则将照片复制或移动到目标目录。

**Acceptance Scenarios**:

1. **Given** 用户选择一组照片，**When** 指定导出目录和组织规则，**Then** 系统按规则将照片导出到目标目录
2. **Given** 导出任务执行中，**When** 用户查看状态，**Then** 用户可以看到导出进度

---

### Edge Cases

- 照片源目录被删除或不可访问时，系统如何处理？
  - **处理方式**: 标记目录状态为 `missing`，保留索引记录供用户恢复
- 导入目录中有重复照片时的处理逻辑？
  - **处理方式**: 通过文件哈希检测重复，按用户配置的策略处理（跳过/重命名/覆盖）
- 超大照片文件（如 RAW 格式）的处理和性能影响？
  - **处理方式**: 延迟缩略图生成，只记录元数据，缩略图按需生成
- 源目录文件被直接删除（非通过应用）？
  - **处理方式**: 通过文件监控检测，标记状态为 `missing`，不删除索引记录

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持添加和管理多个照片源目录（配置文件 + Web UI 两种方式）
- **FR-002**: 系统必须扫描照片源目录并建立索引，但**不移动或修改**源目录中的任何文件
- **FR-003**: 系统必须支持配置和监控导入目录
- **FR-004**: 用户必须能够配置照片组织规则（如按日期、相机型号等）
- **FR-005**: 系统必须按组织规则将导入目录中的照片整理到照片源目录
- **FR-006**: 用户必须能够通过 Web 界面浏览、筛选和搜索已索引的照片和视频
- **FR-007**: 用户必须能够选择照片并按指定规则批量导出
- **FR-008**: 系统必须提供 Docker 容器部署方案（Docker Compose + 手动 Docker run）
- **FR-009**: 系统必须检测照片源目录中的文件变更（新增、删除、移动）并更新索引
- **FR-010**: 系统必须提供状态显示（扫描进度、导入进度等）
- **FR-011**: 文件变化统一通过 queue-manager-pro 队列触发处理
- **FR-012**: 第一阶段支持 HTTP Basic Auth 保护
- **FR-013**: 第二阶段支持 JWT 用户认证
- **FR-014**: 第三阶段支持 HTTPS + TOTP 双因素认证

### Non-Functional Requirements

- **性能**: 导入时和扫描时统一通过队列处理，支持配置最大并发扫描数（默认 2）
- **可扩展**: 任务队列支持扩展，未来可切换到 Redis 存储
- **可靠性**: 支持断点续扫，扫描中断后可恢复
- **运维**: 提供 health check 端点用于容器健康检测

### Key Entities

- **照片源目录**: 用户添加的照片存储目录，系统只读访问，包含路径、状态等信息
- **导入目录**: 监控目录，新照片从此目录导入并整理，包含路径、组织规则等信息
- **照片/视频**: 索引的媒体文件，包含路径、元数据（日期、相机、GPS 等）、缩略图等信息
- **组织规则**: 照片整理/导出的规则，包括命名模式、目录结构等
- **设置**: 系统配置，包括源目录、导入目录、组织规则、认证配置等

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在 1 分钟内添加并配置 3 个照片源目录
- **SC-002**: 系统能够在 5 分钟内完成 10,000 张照片的初始索引
- **SC-003**: 导入目录中的新照片能够在 10 秒内被检测并开始整理
- **SC-004**: 用户能够在 3 秒内完成照片搜索并获得结果
- **SC-005**: Docker 容器能够在 2 分钟内完成启动并可用
- **SC-006**: 90% 的用户能够在第一次使用时成功完成基本配置（添加源目录、配置导入规则）
- **SC-007**: 文件变化事件在 500ms 内进入任务队列处理

## Assumptions

- 用户有稳定的 Docker 运行环境
- 照片源目录在 NAS 或本地存储上，应用有读取权限
- 导入目录应用有读写权限
- 用户通过浏览器访问应用界面
- 应用运行在 x86-64 或 ARM64 架构的 Docker 容器中
- 照片格式支持包括常见的 JPEG、PNG 以及 RAW 格式（NEF、CR2、ARW 等）
- 视频格式支持包括 MP4、MOV、AVI、MKV、WebM 等
- 元数据主要来自 EXIF（照片）和文件属性（视频）
- 第一阶段 NAS 有防火墙保护，内网访问使用 HTTP Basic Auth
- 源目录配置可通过 docker-compose 环境变量或 Web UI 修改

## Security Phases

### 第一阶段（当前）
- HTTP Basic Auth 保护
- 依赖 NAS 防火墙限制公网访问

### 第二阶段
- JWT 用户认证系统
- 多用户支持

### 第三阶段（公网访问）
- HTTPS (Let's Encrypt)
- TOTP 双因素认证
- 速率限制防暴力破解
