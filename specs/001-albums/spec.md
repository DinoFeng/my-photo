# NAS 照片管理系统 - 相册功能规范

**版本**: 1.0
**创建日期**: 2026-06-28
**状态**: 需求已确认

---

## 1. 功能概述

为 NAS 照片管理系统添加**多用户相册功能**：

- 用户可以创建和管理属于自己的相册
- 不同用户之间相册隔离，保护个人隐私
- 支持邀请码登录，无需记忆复杂密码
- 支持生成分享链接，将相册分享给外部访客
- 支持设置相册可见性（私有 / 所有登录用户可见）

### 1.1 背景与动机

当前系统仅有单用户 Basic Auth 认证，照片以平铺列表展示，不支持分类管理。随着家庭成员增加，需要：

- **用户归属**：不同成员的照片分类管理
- **隐私隔离**：个人相册不被他人查看
- **分享能力**：将特定相册分享给外部朋友
- **简单易用**：家庭成员无需学习复杂密码

## 2. 用户场景与使用流程

### 2.1 角色定义

| 角色 | 描述 | 权限范围 |
|------|------|---------|
| **管理员 (Admin)** | 系统初始用户，负责管理用户 | 系统设置、用户管理、所有相册操作 |
| **普通用户** | 由管理员创建的家庭成员 | 管理自己的相册、查看共享相册 |
| **访客** | 通过分享链接访问的外部用户 | 只读查看被分享的相册 |

### 2.2 核心使用场景

#### 场景 1：系统初始化（首次启动）

```
打开网页 → 系统初始化界面
    ↓
创建管理员账号（设置用户名 + 密码）
    ↓
系统自动登录为管理员
    ↓
进入主界面（照片画廊）
```

#### 场景 2：管理员创建新用户

```
管理员 → 进入用户管理页面
    ↓
点击"新建用户"
    ↓
输入：昵称、选择头像表情
    ↓
系统生成邀请码
    ↓
管理员将邀请码发送给家庭成员
```

#### 场景 3：家庭成员登录

```
家庭成员打开网页
    ↓
登录页面 → 选择"邀请码登录"
    ↓
输入邀请码
    ↓
✅ 直接进入系统
    ↓
浏览器记住登录状态，下次打开自动登录
```

#### 场景 4：创建相册

```
用户 → 相册列表页面
    ↓
点击"新建相册"
    ↓
输入：相册名称、描述（可选）
    ↓
选择：可见性（私有 / 所有登录用户可见）
    ↓
点击"创建"
    ↓
进入相册详情页 → 开始添加照片
```

#### 场景 5：添加照片到相册

```
用户 → 浏览照片
    ↓
点击照片 → 选择"添加到相册"
    ↓
或进入相册详情 → 点击"添加照片"
    ↓
从照片库选择多张照片
    ↓
点击"确认添加"
    ↓
✅ 照片出现在相册中
```

#### 场景 6：生成分享链接

```
用户 → 相册详情页
    ↓
点击"分享"
    ↓
点击"生成分享链接"
    ↓
获得可访问链接（例如 /share/album/abc123xyz）
    ↓
复制链接发送给朋友
    ↓
朋友无需登录即可浏览该相册的照片
```

#### 场景 7：撤销分享链接

```
用户 → 相册详情页 → 分享管理
    ↓
点击某条分享链接 → 删除
    ↓
✅ 该分享链接失效，外部无法再访问
```

### 2.3 异常场景

| 场景 | 处理方式 |
|------|---------|
| 邀请码错误 | 提示"邀请码无效，请重新输入" |
| 访问他人私有相册 | 提示"无权访问此相册"并跳转至 404/首页 |
| 已撤销的分享链接 | 提示"分享已过期或已被撤销" |
| 未登录访问相册列表 | 重定向至登录页 |
| 删除相册时相册还有照片 | 先确认，然后删除相册及关联关系（不删除原始照片） |

## 3. 功能需求

### 3.1 用户系统

**F-101 管理员初始化**

- 系统首次启动时，检测到无用户 → 显示初始化向导
- 引导创建第一个用户（自动标记为管理员）
- 需设置用户名 + 密码
- 创建完成后自动登录

**F-102 管理员登录**

- 登录页支持"账号密码"登录方式
- 支持"在此设备上记住我"（长期有效）
- 登录失败提示友好的错误信息

**F-103 用户管理**

- 管理员可创建新用户：昵称 + 头像表情 + 状态（启用/禁用）
- 管理员可查看所有用户列表
- 管理员可禁用/启用用户
- 管理员可查看用户的邀请码
- 管理员可重置/重新生成用户的邀请码

**F-104 邀请码登录**

- 普通用户通过邀请码登录
- 邀请码与用户一一对应
- 输入正确邀请码后自动登录
- 登录后 Session 长期有效

**F-105 退出登录**

- 用户可主动退出登录
- 退出后返回登录页

**F-106 用户信息展示**

- 顶部导航栏显示当前用户昵称和头像
- 点击可查看基本信息

### 3.2 相册管理

**F-201 相册列表**

- 展示当前用户拥有的所有相册
- 展示被设置为"所有登录用户可见"的他人相册
- 每个相册显示：封面、名称、照片数量、创建日期、所有者
- 按最近访问/创建日期排序

**F-202 创建相册**

- 输入：名称（必填）、描述（可选）
- 选择：可见性
  - 私有（仅自己可见，默认选项）
  - 所有登录用户可见
- 新建相册自动以创建者为所有者
- 创建成功后跳转至相册详情页

**F-203 编辑相册**

- 相册所有者可编辑相册的名称、描述、可见性
- 相册所有者可设置相册封面（选择相册内的一张照片）
- 修改后即时生效

**F-204 删除相册**

- 相册所有者可删除自己的相册
- 删除前需要二次确认
- 仅删除相册及其与照片的关联关系，**不删除原始照片文件**
- 删除后无法恢复

**F-205 相册详情**

- 展示相册基本信息（名称、描述、所有者、照片数量）
- 以网格/瀑布流形式展示相册内的照片
- 支持分页或无限滚动加载
- 所有者可在此页面进行管理操作

### 3.3 相册内照片管理

**F-301 添加照片到相册**

- 支持从照片库选择多张照片添加到当前相册
- 支持在照片详情页选择"添加到相册"
- 同一张照片可属于多个相册
- 添加后即时出现在相册中

**F-302 从相册移除照片**

- 相册所有者可从相册中移除照片
- 仅解除照片与相册的关联，**不删除原始照片**
- 移除后即时生效

**F-303 相册内排序**

- 按添加时间排序（最新添加的在前）
- 按拍摄时间排序
- 可切换排序方式

### 3.4 分享功能

**F-401 生成分享链接**

- 相册所有者可生成该相册的分享链接
- 分享链接包含随机 token（足够安全，无法被猜测）
- 链接形式：`/share/album/{token}`
- 可生成多个分享链接

**F-402 分享链接管理**

- 相册所有者可查看该相册的所有分享链接列表
- 显示每个链接的创建时间
- 支持删除/撤销分享链接

**F-403 公开分享访问**

- 访客无需登录，通过分享链接可直接访问
- 以只读形式浏览相册内所有照片
- 支持照片详情查看和大图预览
- 不显示系统其他页面（不泄露相册列表、用户信息等）

**F-404 分享已撤销**

- 已删除的分享链接访问时提示过期/已撤销
- 跳转到友好的提示页面

## 4. 非功能需求

### 4.1 安全性

| 需求 | 说明 |
|------|------|
| NFR-101 | 私有相册只能被所有者访问，其他用户无法通过修改 URL 等方式突破 |
| NFR-102 | 未登录用户无法访问相册相关页面（分享链接除外） |
| NFR-103 | 分享链接 token 足够长且随机，无法被暴力破解 |
| NFR-104 | 管理员密码以加密方式存储，不明文保存 |

### 4.2 性能

| 需求 | 说明 |
|------|------|
| NFR-201 | 相册列表页面加载时间不超过 2 秒（100 个相册以内） |
| NFR-202 | 相册详情页加载时间不超过 3 秒（1000 张照片以内） |
| NFR-203 | 添加/移除照片操作响应时间不超过 1 秒 |

### 4.3 可用性

| 需求 | 说明 |
|------|------|
| NFR-301 | 所有操作有明确的状态反馈（成功/失败提示） |
| NFR-302 | 删除操作需二次确认 |
| NFR-303 | 空状态有友好的引导（例如"暂无相册，点击创建你的第一个相册"） |
| NFR-304 | 界面风格与现有系统保持一致 |

## 5. 数据实体

### 5.1 用户 (User)

| 属性 | 描述 | 约束 |
|------|------|------|
| ID | 用户唯一标识 | 必填，唯一 |
| 用户名 | 登录用（仅管理员有） | 唯一，可空 |
| 密码哈希 | 加密存储的密码（仅管理员有） | 可空 |
| 昵称 | 展示名称 | 必填 |
| 头像表情 | 用户的可视化标识（如 👨👩🧒） | 必填 |
| 是否管理员 | 标识是否为管理员 | 默认否 |
| 状态 | 启用/禁用 | 默认启用 |
| 邀请码 | 登录用的唯一邀请码 | 唯一，可重新生成 |
| 创建时间 | 记录创建时间 | 必填 |
| 更新时间 | 记录最后更新时间 | 必填 |

### 5.2 相册 (Album)

| 属性 | 描述 | 约束 |
|------|------|------|
| ID | 相册唯一标识 | 必填，唯一 |
| 所有者 ID | 创建者用户 ID | 必填，外键关联用户 |
| 名称 | 相册名称 | 必填 |
| 描述 | 相册描述 | 可选 |
| 封面照片 ID | 相册封面引用的照片 ID | 可选 |
| 可见性 | 私有 / 所有登录用户可见 | 必填，默认私有 |
| 排序顺序 | 用于自定义排序 | 可选 |
| 创建时间 | 记录创建时间 | 必填 |
| 更新时间 | 记录最后更新时间 | 必填 |

### 5.3 相册-照片关联 (Album-Media)

| 属性 | 描述 | 约束 |
|------|------|------|
| 相册 ID | 关联的相册 | 必填，外键 |
| 照片 ID | 关联的照片 | 必填，外键 |
| 添加时间 | 照片添加到相册的时间 | 必填 |

- 一张照片可属于多个相册
- (相册 ID, 照片 ID) 组合唯一

### 5.4 相册分享 (Album Share)

| 属性 | 描述 | 约束 |
|------|------|------|
| ID | 分享记录唯一标识 | 必填，唯一 |
| 相册 ID | 被分享的相册 | 必填，外键 |
| 分享 Token | 公开访问用的随机字符串 | 必填，唯一 |
| 创建者 ID | 创建此分享的用户 ID | 必填，外键 |
| 创建时间 | 分享创建时间 | 必填 |
| 过期时间 | 可选的自动过期时间 | 可选 |

## 6. 成功标准

| 编号 | 成功标准 | 验证方式 |
|------|---------|---------|
| SC-1 | 用户可通过管理员密码正常登录系统 | 人工验证 |
| SC-2 | 用户可通过邀请码正常登录系统 | 人工验证 |
| SC-3 | 用户可成功创建、编辑、删除自己的相册 | 人工验证 |
| SC-4 | 用户可将照片添加到相册或从相册移除 | 人工验证 |
| SC-5 | 用户只能访问自己的相册和标记为"所有登录用户可见"的相册，无法访问他人的私有相册 | 人工验证 |
| SC-6 | 用户可生成相册的分享链接，外部访客无需登录即可通过链接浏览 | 人工验证 |
| SC-7 | 用户可撤销已生成的分享链接，撤销后外部访问无效 | 人工验证 |
| SC-8 | 删除相册不会删除原始照片文件 | 人工验证（检查文件系统） |
| SC-9 | 相册列表加载时间 ≤ 2 秒 | 性能测试 |
| SC-10 | 相册详情页（含 1000 张照片）加载时间 ≤ 3 秒 | 性能测试 |

## 7. 范围外功能

以下功能**不在本次范围内**，可在未来迭代中考虑：

- 相册的拖拽排序（当前只按时间排序）
- 相册内照片的手动拖拽排序
- 评论、点赞等社交功能
- 图片编辑/滤镜功能
- 相册打包下载为 ZIP 文件
- 邀请码过期时间设置（当前永久有效，直到被重新生成）
- 多管理员支持（当前仅第一个用户为管理员）

## 8. 假设与依赖

| 假设 | 说明 |
|------|------|
| AS-1 | 照片扫描、缩略图生成等现有功能保持不变，相册功能基于现有照片库进行 |
| AS-2 | 系统运行环境与当前一致，使用 SQLite 数据库 |
| AS-3 | 分享链接功能基于 HTTP 基本认证的旁路实现（即访问分享链接时跳过 Basic Auth 的用户检查） |
| AS-4 | 当前系统的 Basic Auth 保持作为系统级门禁，相册用户体系在其之上构建 |
